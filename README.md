# Blüten Sturm — bluetensturm.com

Marketing, creative and corporate training agency site. React + Vite, three.js
for the petal storm, hand-authored CSS with its own design tokens.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # → dist/
npm run preview
```

## Pages

Three real HTML documents, not a client-side router — each is indexable,
shareable, and survives a hard refresh on any static host with no redirect
rules.

| Route | Entry | What it is |
|---|---|---|
| `/` | `index.html` | Hero orbit, about, services, why, work, academy, enquiry form |
| `/questionnaire` | `questionnaire.html` | The long-form brief, ten questions |
| `/thank-you` | `thank-you.html` | Post-submit confirmation and next steps |

## Where the content lives

`src/content/site.js` holds every piece of copy and all structured content.
The same service list feeds the hero orbit, and the same option lists feed both
forms — so wording changes never require touching layout, and the two forms
cannot drift apart.

## The hero orbit

Eighteen service cards orbit the bloom on a computed ellipse, so adding a
service to the manifest re-spaces the whole ring. Each card's position on the
ellipse yields one depth value, and that single number drives z-index, scale,
opacity and blur together — which is what makes it read as an orbit rather than
a circle of divs. Cards are real focusable links, so the ring is keyboard
navigable and legible to a screen reader.

It stops spinning on hover or focus, drops its labels below 860px, and is
hidden entirely below 620px, where the services grid already carries all
eighteen disciplines.

## Imagery

All artwork under `public/media/` is generated by this repo:

```bash
npm run art      # tools/art/render.mjs → public/media/*
```

`tools/art/scenes.js` defines each scene as a canvas drawing over a seeded
PRNG; headless Chromium renders them at output size. It is deterministic — a
re-run reproduces the same files rather than reshuffling the site's imagery on
every build. No image service, no network.

The four Work frames are commissioned abstract compositions, one per
discipline. **They are not photographs of client deliverables**, and those
cards say "case detail on request" rather than carrying invented metrics.
Replace both the image and the copy in `src/content/site.js` as real cases
become publishable.

## Forms

Both forms post to the Formspree endpoint in `site.formEndpoint` and then route
to `/thank-you`. If the service cannot be reached, the visitor gets a
pre-filled mail to `info@bluetensturm.com` instead of losing what they typed. A
honeypot field catches bots. To change the destination, edit `formEndpoint`; to
move to a different backend, replace `sendEnquiry` in `src/lib/form.js`.

The thank-you page fires `generate_lead` and a `dataLayer` push **only if**
gtag/dataLayer already exist — no tags are injected from the page, so a consent
manager stays in control.

## Motion and accessibility

`prefers-reduced-motion` is honoured throughout: the petal storm and embers do
not start, the orbit stops rotating, counters jump to their final value, and
reveals render in place. Both canvases pause when the tab is hidden. Without
WebGL the storm is skipped and the rendered backdrop carries the hero on its
own. Every section is a real landmark with a real heading, and there is a skip
link and a visible focus ring.

## Deploying

`npm run build` emits a fully static `dist/`. No server-side runtime anywhere.

**Netlify, drag and drop** — `npm run pack` produces `bluetensturm-netlify.zip`
with the three documents at its root and a `_headers` file carrying the caching
and security headers (Drop ignores build settings, so they cannot come from
`netlify.toml`). Drop it on <https://app.netlify.com/drop>.

**Netlify, connected to Git** — `netlify.toml` already declares the build
command, publish directory, Node version and the same headers.

**STRATO** — upload the contents of `dist/` to the document root.
`vite.config.js` sets `base: '/'`; change it if you serve from a subfolder.

Fingerprinted files in `/assets` are cached immutably for a year; the HTML
documents are always revalidated, so a deploy cannot leave browsers asking for
hashed assets that no longer exist.
